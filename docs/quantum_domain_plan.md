# Quantum domain plan

## Domain focus

Quantum systems and adjacent security / compute features.

## Why this domain

This domain is attractive because it combines:
- technical novelty
- active public patenting
- complex feature combinations
- major strategic relevance for computing, security, sensing, and networking
- potential for meaningful white-space intelligence

## Initial target research areas

- quantum routing
- entanglement-aware transport
- photonic and time-frequency encoding
- hybrid quantum-classical coordination
- secure quantum communication and key exchange
- quantum memory systems
- fault-tolerant architecture patterns
- quantum verification and benchmarking

## Data sources

Primary public sources:
- USPTO PatFT and AppFT
- Google Patents
- WIPO PATENTSCOPE
- EPO Espacenet
- IP Australia
- relevant academic and standards references for validation context

## Feature taxonomy

The system should normalize claims into the following categories:
- architecture
- signal / qubit implementation
- error mitigation or correction mechanism
- memory or buffering strategy
- security or verification mechanism
- communication or transport layer
- performance metric and operating condition
- system integration and deployment model

## White-space scoring dimensions

A domain opportunity should be scored across:
- coverage level
- under-served feature dimensions
- novelty risk
- technical plausibility
- strategic value
- market relevance
- confidence score

## Example opportunity types

- under-covered hybrid quantum control
- new combination of routing and entanglement coordination
- performance benchmarking gaps
- secure interconnect architecture without explicit prior-art coverage
- quantum memory access patterns with insufficient coverage

## Example output format

Each opportunity report should include:
- title
- summary
- public-source references
- feature dimensions covered
- feature gaps
- confidence score
- review flag
- suggested next technical validation step

## Validation workflow

Before a report becomes customer-facing:
- source review
- feature extraction review
- confidence score review
- strategic relevance review
- legal boundary check

## Customer narrative

This product tells a technical team:
- what is already public in the domain
- what adjacent ideas are poorly covered
- what gaps deserve technical investigation or counsel review

That is a strategic and credible value proposition.
